### 技术修正（重要）
- **BLE 鼠标无法读取主机光标位置**（只能发相对位移）。
  原 PRD 的"记录绝对坐标"方案在协议层不可行。
  改为 `main/app/pointer.c` 的**虚拟光标 + 增量路径**方案。
- **长按/超长按不能立即执行动作**。原实现 600ms 执行长按、1500ms 又执行超长按，
  一次按压触发两个动作（违反 PRD 约束，被单元测试抓出）。
  改为**松手时统一决策**，长按与超长按天然互斥。
  副作用（正向）：按住期间屏幕实时提示「松开 = xxx」，盲操体验更好。

### 环境要点（本机）
- ESP-IDF **v6.0.2**：`D:\software\esp-idf\.espressif\v6.0.2\esp-idf`
  工具链 `C:\Espressif`（xtensa-esp-elf esp-15.2.0_20251204, python v6.0.2）
- `tools/idf.bat` 已封装环境并绕过三个坑：
  1. 清除 `MSYSTEM`/`MSYS2_PATH_TYPE`/`MINGW_PREFIX`（否则 idf.py 拒绝 MSYS）
  2. `IDF_PYTHON_CHECK_CONSTRAINTS=0`（新版 constraints 在 tools/ 下，idf.py 在根目录找）
  3. `ESP_IDF_VERSION=6.0.2`（不能带 `v` 前缀）
  4. `ESP_ROM_ELF_DIR` 需显式设置
- 根 `CMakeLists.txt` 需 `-Wno-unused-label`（IDF v6.0.2 fatfs `fail:` 标签缺陷，
  同板既有项目 `esp32s3-lichuang-desktop` 已踩过并记录）
- `sdkconfig.defaults` 需显式列出全部 FATFS Kconfig（否则 `CONFIG_FATFS_USE_LABEL` 未定义）
- 主机侧单元测试：系统无 gcc，用 Docker `node:22-alpine` + `apk add gcc` 实测可用
  （Docker Hub 不可达，只能用本地已有镜像；注意 MSYS_NO_PATHCONV=1 与原生路径混用）
