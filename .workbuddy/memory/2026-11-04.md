## macOS 兼容 + I2C 修复（第二轮，提交 218de70 / 0325b25）

用户在 MacBook 上实测反馈「连上蓝牙但无输入、触摸不动、按钮太小」。定位出 6 个真 bug：

1. **广播包超限（致命）**：31 字节上限，字段顺序 flags→appearance→name→txpower→uuid128，
   "BiliMouse" 占位后 128 位 UUID 被截断为 0 长度 → macOS 不识别为 HID 设备。
   修复：改用 16 位 HID 服务 UUID 0x1812（BLE HID 规范标准做法），广播包 25/31 字节。
2. **缺 LE Secure Connections**：ESP_LE_AUTH_BOND 不含 SC 位，Apple 强制要求 SC。
   改为 ESP_LE_AUTH_REQ_SC_BOND。
3. **CCCD 订阅无跟踪**：官方示例 ESP_GATTS_CONF_EVT 为空。加订阅状态回调，
   hid_device_is_ready() = 已连接+已加密+主机已订阅。
4. **UI 重构**：遥控模式屏幕直显大按钮（100x64 主行 + 74x50 次行），屏幕任意空白处拖动=移动指针（原仅鼠标模式可拖）。
5. **I2C 总线重复创建（致命）**：三个驱动各调 i2c_new_master_bus()，后两个拿到
   ESP_ERR_INVALID_STATE 且句柄为野值 → 触摸 100 行/秒错误日志风暴饿死蓝牙任务。
   新增 bsp/bsp_i2c.c 统一总线管理层。
6. **bsp_touch_init 从未被调用**：app_main 漏了初始化调用，触摸任务裸奔。已补上。

教训：IDF v6 i2c_new_master_bus 失败时不写输出句柄；复用总线需自建管理层。

## 第三轮：电脑连不上（广播 UUID 编码错误）

用户反馈「之前能连，现在连不上」。日志只有启动到 startup complete，无 BLE connected。
定位出三个问题，其中第 1 个是致命根因：

1. **广播里传了 2 字节的 16 位 UUID 缓冲区（致命）**
   `service_uuid_len = 2` + `p_service_uuid = (uint8_t*)&uint16_t`。
   但 IDF btc 层（btc_gap_ble.c → btc128_to_bta_uuid → uuidType）**固定读 16 字节**，
   按 BASE_UUID 逐字节比对判定是不是 16 位 UUID。传 2 字节缓冲区：
   - 越界读 15 字节 → uuidType 判定失败 → 广播里写入一个 128 位垃圾 UUID
     → 主机扫不到 0x1812 HID 服务 → 拒绝/无法连接
   - 且 malloc 长度为 service_uuid_len/16*2 = 0 → 往 0 字节堆块写数据 = 堆破坏
   正确做法：填满 16 字节小端 128 位格式（末 4 字节 ...12 18 00 00），
   service_uuid_len = 16，btc 自动压缩成 2 字节 0x1812 写进广播包。
   → 同一份固件立刻能连上，150ms 内完成配对。

2. **CCCD 订阅检测用错了句柄（导致「连上但没反应」）**
   原代码在 ESP_GATTS_CONF_EVT 里比较 `conf.handle` 与 `HIDD_LE_IDX_*_CCC`（属性表索引），
   索引和真实句柄永远不可能相等 → s_report_enabled 恒 false → is_ready() 恒 false。
   改为在 ESP_GATTS_WRITE_EVT 里比较 `att_tbl[HIDD_LE_IDX_*_CCC]` 并解析 CCCD 位。

3. **NVS 初始化顺序错误**
   nvs_flash_init() 藏在 hid_device_init() 里，而 settings_load() 在前面执行
   → 启动必报 ESP_ERR_NVS_NOT_INITIALIZED，且校准数据每次上电都丢。
   改为 app_main 开头统一初始化。

另外加固：GAP 回调改到 profile init 之前注册（避免 REG_FINISH 早于回调导致广播起不来）、
广播开启/失败显式打日志、广播看门狗（3s 未在跑就重拉）、配对 8s 超时主动断开、
连续 3 次配对失败自动清 bonds、连接后请求 7.5~15ms 低延迟连接间隔。

教训：**给 IDF 传 UUID 缓冲区时，一律按 16 字节 128 位格式准备**，哪怕只想要 16 位 UUID。

## 第四轮：触摸不灵的真因（I2C 速率 + 坐标映射）

用户反馈"体感暂停可用，但触摸、点下一集、鼠标移动都不灵"。
关键线索：**体感暂停走的是键盘空格键，能生效 → HID 键盘通道没问题**，
所以问题全在触摸这一侧。

用寄存器转储抓到真相：

```
regs@02: 01 80 2a 00 d6 00   → TD_STATUS=1, X=0x2a=42, Y=0xd6=214
```

1. **400kHz 下多字节读只回第一字节**：状态寄存器能读到（所以"能感知按下"），
   但后面 4 个坐标字节全是 0 → raw 恒为 (0,0) → 映射到屏幕左下角一个点。
   降到 **100kHz 立刻正常**。FT6x36 和 QMI8658/PCA9557 共用总线时很容易踩这个坑。
2. **坐标是像素不是 12bit**：实测 raw_x∈[0,239]、raw_y∈[0,319]，
   即面板竖屏 240x320 的像素坐标。旧代码按 12bit 折算（/4096），缩小了 12.8 倍。
3. **轴向**：屏幕 320x240 横屏 = 面板旋转 90°，screen_x=raw_y、screen_y=239-raw_x
   （镜像方向因装配而异）。

改法：bsp_touch 只输出原始坐标（100kHz + 连读/拆分读自适应 + 零坐标时打印寄存器块）；
新增 app/touch_cal.c 用**三点校准**解仿射矩阵（旋转/镜像/缩放全部吸收），存 NVS；
未校准时的兜底映射按上面实测关系写死。首次开机自动进向导，未校准期间任何触摸都会
把向导叫回来；长按实体键 4 秒可随时重做。

同时修掉两个交互缺陷：
- 鼠标模式"轻点空白处"以前什么都不做（提示写着"单击=左键"），现在会发左键。
- button_fsm 增加 4 秒档（GESTURE_ULTRA_LONG / HOLD_ULTRA），单元测试 12→15 项。

## 第五轮：交互重构（实体键=鼠标左键）+ 字库缺字 + 停用体感

用户反馈四点：碰屏幕按钮就消失 / 鼠标拖不动 / 物理按键要能单击双击 /
满屏问号 / 不要体感控制播放暂停。

1. **按钮消失的根因**：上一轮加的「未校准期间任何触摸都把向导叫回来」——
   而校准一直失败(见下)，所以一碰屏幕就跳到校准向导，按钮全没了，鼠标也拖不动。
   改为：校准只能主动点「校准」按钮或长按「鼠标」按钮进入。
2. **校准永远失败的根因**：在松开那一刻取坐标，手指抬起后 FT6336 坐标寄存器
   归零，三个采样点全是 (0,0)，行列式恒 0。改为记录按住期间最后一次坐标。
   目标点移到 (24,44)/(296,44)/(24,196)。
3. **实体按键 = 真鼠标左键**：按下发 down、松开发 up，单击/双击/按住拖动全部
   由 macOS 判定。hid 新增 hid_mouse_button() + 按键掩码进移动报告
   （否则拖动时主机认为按键已松开）。旧的手势 FSM 不再用于按键。
4. **问号**：字库只有 114 字，界面文案早已超出。gen_font.py 改为扫描源码
   字符串自动收集（233 字，43KB），并写了 tools/preview_ui.py 用同一份点阵
   数据离线渲染 PNG 预览（验证无缺字/无溢出）——以后改文案先跑一遍预览。
5. **体感停用**：翻身/拿放误触发太多。模块保留，imu_task 注释掉。
6. 鼠标模式右下角加「遥控」小按钮，否则进去出不来。
7. 单测 15/15 通过，固件 814KB(22% free)，已提交 617e17a。

待验证：触摸方向映射(理论推导 screen_x=raw_y, screen_y=239-raw_x，
依据 MADCTL swap_xy+mirror_x)，如果镜像了就点「校准」重做三点校准。

## 第六轮：实体键=右键、屏幕轻点=左键、移动加增益

用户要求：实体按钮改成右键；左键=屏幕轻点，双击=点两下；移动更灵敏。

- 抓到屏幕左键失效的真因：actions.c 用 HID_MOUSE_LEFT=253 当掩码发，
  0xFD 是 6 个键同时按下的组合，macOS 当然不认。换成 0x01 修复。
- 实体键 HID_MOUSE_BTN_RIGHT 直通（down/up）。
- 双击不需要固件参与：轻点发 30ms down/up，两次间隔远小于 macOS
  双击窗口，系统自己判双击。
- TOUCH_GAIN=3：屏幕 1 像素 -> 光标 3 像素，>127 自动分包发送。
  增益是 app_main.c 顶部一个 #define，用户嫌快慢改一个数字即可。
- 字库重生 232 字，预览无缺字；固件 814KB(22% free)，真机启动正常、
  触摸校准矩阵从 NVS 加载成功、Mac 自动重连并订阅全部报告。

## 第七轮：轻点失效真因 + 自适应增益 + 右键可观测

用户反馈：灵敏度太高微调难；轻点/双击失效；实体右键无效。

- 轻点失效真因：moved 阈值累计的是乘过 3 倍增益的位移，4 像素手抖
  就超阈值，轻点被判拖动。改回原始像素。**教训：阈值类判定永远用
  物理原始量，不要用加工后的量。**
- 增益改自适应：<=2px 1:1（微调），>2px 2 倍（快滑）。固定倍率
  必然顾此失彼，两段式是小屏触控板的正解。
- 右键固件逻辑核查无误；加 LOGI + 屏幕「右键↓/↑」反馈用于定位
  是固件还是 macOS 的问题。若屏幕有反馈但无菜单 -> macOS 辅助点按。

## 第八轮：右键改 Ctrl+左键 模拟

用户在 macOS 系统设置里找不到"辅助点按"（很多版本对第三方
鼠标不显示该选项），HID 按钮 2 方案被否定。改为 Control+左键：
按下=Ctrl down，松开=左键 down/up(30ms)+Ctrl up。
新增 hid_keyboard_modifier()；release_all 同时清修饰键。
这个方案不依赖 macOS 对鼠标按钮的识别，100% 可靠。
