## OTA / 内存 / 电台 收尾（v2.6.1 → v2.7.1，全部实机验证）

### 四个原始 bug 的最终根因与修复
1. **电台列表为空**：既有多源列表兜底（内置 3 个 CNR 台 + raw.githubusercontent 7 台）。
   运行期 TLS 拉列表失败的真正原因是 **esp-aes 需要内部 DMA 缓冲**
   （`esp-aes: Failed to allocate memory` → tls read -0x84），
   WiFi+蓝牙常驻后内部只剩 4KB。→ 关闭 `CONFIG_MBEDTLS_HARDWARE_AES`（改软件 AES）。
2. **点「开始检查更新」没反应**：两层原因
   a) 9KB 任务栈分配失败（内部 RAM 不足）→ **BLE 挂起/恢复**（hid_ble_suspend/resume，
      suspend 时先 esp_hidd_profile_deinit，官方 demo 的 deinit 漏清 enabled 标志已修）；
      恢复前必须 `esp_wifi_disconnect()`，否则连接态动态缓冲把刚还的内存切碎，
      Bluedroid 的 future_new assert 崩溃重启。
   b) `ota_download_run()` 守卫要求 `phase==READY`，而 `ota_update_download()`
      起任务前已把 phase 置成 DOWNLOAD → 永远失败（"download without a READY check"）。
3. **统一左上角返回**：ui.c draw_header 统一「< 返回」胶囊（BACK_W=58），删台列表底部返回按钮。
4. **首页底部文字 + 图标居中**：HOME 模式不画 footer，HOME_TILE_Y=(240-96)/2=72。

### 关键教训（会再踩）
- `esp_http_client_get_header()` 读的是**请求头**，响应头默认不保存！
  跟随 302 必须用 `esp_http_client_set_redirection()` + `esp_http_client_get_url()`。
- GitHub releases CDN（Azure Front Door）对 ESP-IDF TLS 指纹有 bot 防护，
  间歇/持续返回 **618 + XHTML**（PC curl 200）。→ OTA 资产必须走
  **raw.githubusercontent.com**（radio 同源，从未失败）：`ota/manifest.json`
  固定入口 + manifest.url 指向 tag 化 bin 路径。release.py 已双通道发布。
- **release.py 必须 `env.pop("MSYSTEM")`**：Git Bash 下 idf.py 打印 MSys 警告后
  以 0 退出但**不编译**，导致 2.6.5/2.6.6 连发两版旧 bin。现已加防护：
  编译后校验 bin 内含目标版本号，否则退出。
- LCD 整帧 `draw_bitmap` 不可行：spicommon 每次传输临时 malloc 内部对齐缓冲，
  150KB 分配必失败（`spicommon_dma_setup_priv_buffer Failed`，画面卡住）。
  → ui.c 改 **4 行分条刷屏**（2560B/条）。
- 电台 8K/10K 任务栈 + PCM 缓冲全部改 PSRAM（`xTaskCreateWithCaps`），
  内部 RAM 只剩 4KB 最大块时内部栈永远分配不出来。
- 只烧 `0x20000` 不会生效：OTA 后 otadata 指向 ota_1，直烧要连
  `ota_data_initial.bin` 一起写（或全量四件套）。
