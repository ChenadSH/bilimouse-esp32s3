# 2026-11-06

## v2.6.0 三个用户反馈问题的修复（commit da17fff，已推送）

1. **电台「列表未就绪」+ 背景图花屏的真根因**：`esp_wifi_init: ESP_ERR_NO_MEM`
   —— BLE+LCD+音频共存时内部 RAM 不够，WiFi 驱动静态 rx buffer 10 个只分到 9 个，
   WiFi 根本起不来。网络功能全废（电台列表、OTA 检查全部失败于此）。
   修复：sdkconfig 缩 WiFi 缓冲（STATIC_RX 10→6、DYNAMIC_RX/TX 32→16、MGMT_SBUF 32→16）。
   烧录实测 `Init static rx buffer num: 6` + `mode : sta` 成功。
   附带：radio 拉列表任务堆栈 5KB→10KB（TLS 握手不够）、加 jsdelivr/fastly 镜像 fallback、
   列表未就绪时按播放自动重拉。本机 curl 验证 4 个源全部可达。
2. **OTA 两段式**：`ota_update_check()`（WiFi→清单→版本比较，升级页三行分步显示，
   红绿灰状态色）→ 只有 READY 才出现「立即升级」按钮 `ota_update_download()`。
   `ota_progress_t`/`ota_update_start_manual` 已删除，换 `ota_state_t`/`ota_update_get_state`。
   自动检查（开机 30s）查到 READY 仍自动下载。
3. **红外**：代码层无新改动（25ms 阈值已在 master）；用户设备还在 v2.5.1 所以一直失败。
   硬件：需外接 VS1838B/HX1838 38kHz 接收头 OUT→GPIO11、3V3、GND（板载无红外），
   发射 LED→GPIO10（串 100Ω，远距离加 S8050）。
4. **字库**：gen_font.py 补扫 Kconfig.projbuild（SSID「九天诛仙」）与 radio/radio_stations.json（台名），357 字。
5. 版本号 CMakeLists `PROJECT_VER "2.6.0"`。已直接 `idf.py -p COM4 flash` 烧到设备并串口验证启动 OK。
   GitHub Release v2.6.0 未发（等用户 token 或用户自跑 tools/release.py 2.6.0）。

## 环境备注
- COM3/COM4 会被 VS Code 的 ESP-IDF 扩展监控占用（PermissionError 13），抓串口日志前要确认 VS Code 没开 monitor。
- 设备平时就插在本机：ESP32-S3 USB-JTAG = COM4，CH340K = COM3。
- PowerShell 工具里用 stdin 管道喂 python 的方式对长脚本不稳，改写成 .py 文件再跑；串口输出中文会在 cp936 控制台炸 UnicodeEncodeError，一律写文件再 Read。
