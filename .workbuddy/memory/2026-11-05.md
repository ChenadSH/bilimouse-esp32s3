## v2.1 红外存储加固（commit 见 git log）

- 用户问「红外学习后重启会丢吗 / 重烧也不能丢」。结论：原实现走 NVS，重启本来不丢，但存在两个真隐患：①`ir_remote_init` 在 RMT 初始化失败时提前 return，s_bank 为空，之后任何 save 会把已学码盖成空库；②NVS 一旦被 nvs_flash_erase（NO_FREE_PAGES / NEW_VERSION_FOUND 兜底）整体清掉就没了。
- 方案：NVS + 独立裸分区 `irbank`（0x200000，64KB，data subtype 0x40）双副本；分区内 A/B 双 4KB 扇区轮换，记录 = magic+seq+len+CRC32，擦旧页→写→回读校验；开机两份都读，取 seq 大且 CRC 对的那份，另一份自动补齐。
- 发现 `partitions.csv` 一直是**死文件**（sdkconfig 用默认 singleapp 表），本次真正启用 CUSTOM；nvs 保持 0x9000 不动，app 1984KB。
- bank 格式 v2（IRB2），自动迁移 v1（IRB1）；当前槽位单独存 NVS `ir_act`。
- 新增 tests/test_ir_store.py 6 项（A/B 交替、新页被擦回退、写一半掉电、CRC、超长），全通过；build 834KiB，余 58%。
- 烧录不丢的前提：`idf.py flash` 不写 nvs/irbank；`erase-flash` 或改 nvs offset 才会丢。

## Apple 平台点击/拖拽失效排查（未最终验证）

- 用户报 macbook/iphone 点击、按住拖拽无效（移动正常），Windows 未测。
- 网上找到 espkvm 实测笔记：Apple 把运动报告折叠到最新位置；"按住期间带位移"会被归为拖拽。 BleMouse 库（AbleMouse，macOS/iOS 可用）用的是纯按键零位移报告。
- 根因候选（最大嫌疑）：v2.0 给 click 加的 ±1px 反折叠抖动——按住时有位移 → Apple 当拖拽 → 点击变成 0px 拖拽。移动/键盘正常，只有带按钮+位移的报告异常，完全吻合症状。
- 修复：click 改回标准两报告（down, 40ms, up，零位移）；hid_dev_send_report 返回 esp_err_t、esp_hidd_send_mouse_value 失败打 WARN（btn/dx/dy/原因）、hid_mouse_button 记录每次 down/up 边沿。若仍失效，串口能区分"报告没发出去"还是"主机不认"。
- 教训：**"反折叠抖动"是当时 5 字节 bug 误诊的副产品，bug 修掉后抖动反而成了新 bug**。点击一律用标准纯按键报告。

## 点击/拖拽第三轮排查 + WiFi 内置 + GitHub OTA（见 git log）

- 用户确认 v2.3 后点击/按住拖拽在 macbook/iphone 仍失效（移动正常）。反思：前两轮分别修了报告长度、抖动，都"有效但没修完"。剩余最大嫌疑：**同一连接事件内 down+up 被主机折叠**（espkvm 实测：主机丢弃按键边沿、报告队列跨按键变化折叠）。我们 40ms 保持时长若遇到 macOS 谈判出的长间隔（从未记录过实际值！）就会中招。
- 修复：click 保持 40→120ms（真鼠标水平，保证跨连接事件）；新增 ESP_GAP_BLE_UPDATE_CONN_PARAMS_EVT 日志 + click 时打印当前间隔——下轮用户日志能一锤定音。**教训：调试 BLE 一定要记录协商后的连接参数，不能假设主机接受了我们的请求。**
- API 坑：Bluedroid 事件结构是 update_conn_params.conn_int（无 supervision_timeout）；esp_ble_get_current_conn_params 用 esp_gap_conn_params_t.interval。
- WiFi 凭据写死 Kconfig 默认（WPP-Guest/connected，sdkconfig 同步）；OTA 自动检查默认关（用户只要手动按钮）。
- OTA 上 GitHub：两个 http config 都挂 esp_crt_bundle_attach（bundle FULL 已启用）；docs/OTA.md §2.2 三种 GitHub 部署（独立仓库/Releases latest-download 重定向/Pages）+ 对比表。
