## 1. 产品概述

### 1.1 一句话定义

**BiliMouse** 是一块能"躺着操作"的无线遥控鼠标：把立创实战派 ESP32-S3 变成一个 BLE HID 复合设备（键盘 + 鼠标 + 消费类按键），让你躺在床上不用伸手够键盘鼠标，就能切换 B 站视频、暂停、调音量。

### 1.2 要解决的真实痛点

| 痛点 | 现状 | BiliMouse 的解法 |
|---|---|---|
| 躺在床上够不到键鼠 | 手离开被窝去点下一集，冷启动体验极差 | 举在床头的手边，按一下 |
| B 站网页没有"下一集"快捷键 | 只能鼠标点播放器右下角 | 设备内置**鼠标点击坐标记忆**，一键点到"下一集"按钮 |
| 只有一个按键，功能受限 | 单按钮只能做一个动作 | **单键多义**（单击/双击/长按/超长按）+ IMU 体感手势 |
| 手机/平板没有物理按键 | 触屏误触、找不准 | 独立的实体按键，盲操可用 |

### 1.3 目标用户

- **主用户**：重度 B 站用户，习惯躺着/半躺着看视频（追番、看课程、做直播）
- **次用户**：需要"床上/沙发上远程控制 PC"的轻度用户
- **排除**：专业游戏玩家（延迟敏感）、需要无线充电的长期移动场景（本产品 USB 供电）

### 1.4 竞品与差异化

| 方案 | 能力 | 问题 |
|---|---|---|
| 现有蓝牙遥控器（电视用） | 媒体键 | 无鼠标能力，PC 上切不了视频 |
| 手机当遥控器（App） | 全能 | 要解锁、找 App、开 App，链路太长 |
| 现有 ESP32 BLE HID 鼠标例程 | 只有鼠标 | 无 B 站适配，无多义按键，无屏上状态反馈 |
| **BiliMouse** | 复合 HID + 单键多义 + IMU + 屏上反馈 | — |

**核心差异点**：不是"又一个 BLE 鼠标"，而是**为 B 站网页播放器场景做过交互优化的专用遥控器**。

## 2. 功能需求

### 2.1 F1 — BLE HID 复合设备（P0）

设备必须同时被主机识别为**鼠标、键盘、消费类控制**三种角色，这样一套固件覆盖所有操作需求。

| 报告 ID | 类型 | 用途 | 字段（实际字节数） |
|---|---|---|---|
| 1 | Mouse Input | 指针移动、点击、滚轮 | Button(1B) + X/Y 位移(2B) + Wheel(1B) = **4 字节** |
| 2 | Keyboard Input | 快捷键（空格/方向键/字母） | Modifier(8bit) + 保留 + 6 键 = 8 字节 |
| 3 | Consumer Control | 媒体键（播放/暂停、音量） | 2 字节用法位图 |

> **v2.0 阻断性修复（报告长度必须与 Report Map 一致）**
>
> Report Map 中鼠标 collection 定义为 4 字节（3bit 按键 + X/Y/Wheel 各 8bit），
> 而官方 demo 遗留代码按 5 字节发送（多出一个不存在的 AC Pan 字节）。
> macOS 对长度不符的 HID 报告**整包丢弃**，表现为：串口日志一切正常、
> 蓝牙已连接，但移动/点击/滚轮主机全部无反应，且"忽略设备重配对"无效——
> 因为这是固件 bug，不是配对问题。修复：报告统一按 4 字节构造。
>
> 另外两处配合修复：
> 1. 单击按下报告带 **+1px / -1px 净零抖动**——部分主机的事件管线只在
>    报告含位移时才派发，纯按键变化（dx=dy=0）会被折叠；
> 2. 按住时长 30ms → 约 60ms，避免 macOS 折叠间隔过近的 down/up。

**验收标准**
- [x] Windows / macOS 蓝牙设置中可见并可配对，设备名 `BiliMouse`
- [x] 配对后被识别为「鼠标」，同时键盘输入生效
- [x] 鼠标移动无跳变（相对位移，由主机侧处理平滑）
- [x] 支持断线自动重连（连接断开后自动重新广播，≤5s 恢复）
- [ ] 屏幕轻点 = 单击、快速点两下 = 双击，在 macOS 上稳定注册（v2.0 修复后待真机回归）

### 2.2 F2 — 实体按键交互（P0，v2.0 修订）

板载仅一个 GPIO0 按键（BOOT 复用）。v1.0 设计的"单键多义 + IMU 手势"经真机验证
**过度设计**：躺着单手握持时甩腕误触发远多于主动使用，多义手势的记忆成本也高。

#### 2.2.1 v2.0 定稿行为

| 手势 | 动作 | 说明 |
|---|---|---|
| **按下** | 发送一次**空格键** tap | B 站网页播放器把空格绑定为播放/暂停，且页面级生效 |
| 长按 | 无（不重复触发） | 避免主机键盘自动重复导致播放/暂停反复横跳 |

**选型理由（为什么从"右键"改成空格）**
1. 空格 = 播放/暂停是最高频动作，一个实体键就该给最高频的动作；
2. 旧方案（Ctrl+左键 模拟右键）依赖 macOS 把修饰键与鼠标点击串起来判定，
   在输入框聚焦、拖动等场景行为不稳定，且用户实际需要右键时可以用
   鼠标模式右侧的「右键」按钮（见 §2.4）；
3. 键盘报告没有"按住状态清不干净"的副作用，断连兜底更简单。

#### 2.2.2 历史设计（v1.0，已被替代）

<details>单键多义（单击=下一集/双击=上一集/长按=暂停/超长按=切模式）与
IMU 甩腕（快进 10 秒）的状态机设计与 12 项单元测试（`tests/test_button_fsm.py`）
保留在仓库中，动作在松手时统一决策的互斥结论仍然有效，未来需要多义按键时可直接复用。</details>

**验收标准**
- [ ] 按一下实体键，视频播放/暂停切换，屏幕出现"空格：播放/暂停"提示
- [ ] 连续快速按 10 次，动作次数正好 10 次（无重复、无丢失）
- [ ] 蓝牙未就绪时按键有屏上提示且不发送报告

### 2.3 F3 — B 站视频切换（P0）

**这是产品的核心价值主张**，必须做到"一次按键 = 一次切换"。

#### 2.3.1 切换机制：增量路径校准

B 站网页播放器右下角有"下一集"按钮，但它**没有键盘快捷键**
（`[`/`]` 仅对多 P 视频有效）。因此采用**鼠标点击**方案。

> **实现阶段的关键修正**
>
> 最初的设计是"记录鼠标坐标 (X, Y)，之后移动到该坐标并点击"。
> 但 **BLE HID 鼠标只能发送相对位移，设备无法读取主机的真实光标位置** ——
> 这个方案在协议层面不可行。
>
> 修正后的方案：**增量路径（delta path）**。
> 设备自己维护一个"虚拟光标"，记录自启动以来累计发送的所有位移。
> 校准时记录起点，用户把光标移到目标按钮后记录终点，
> 两者的差值就是可重放的点击路径。

#### 2.3.2 校准流程（全部在设备 2 寸屏上完成）

```
1. 电脑上把鼠标停在 B 站「下一集」按钮上
2. 设备超长按 → 进入鼠标模式
3. 鼠标模式双击 → 进入校准界面（屏幕显示 下一集 / 上一集 / 完成 三个按钮）
4. 点「下一集」→ 设备记录当前虚拟位置为起点，屏幕提示"用鼠标移到下一集后点此确认"
5. 用设备屏幕滑动（或直接动电脑鼠标）把光标移到「下一集」按钮上
6. 再点一次「下一集」→ 计算位移差并存入 NVS，屏幕显示「下一集 已记录」
7. 点「完成」退出校准
```

之后每次按「下一集」，设备重放该位移差并发送一次左键点击。

#### 2.3.3 规格

| 项 | 规格 |
|---|---|
| 存储位置 | NVS（非易失），掉电不丢 |
| 存储内容 | next(dx,dy) / prev(dx,dy) 两组增量路径 |
| 移动方式 | 相对移动，拆成 10 步，每步 ≤127 像素，步间 10ms |
| 模拟真人 | 分步插值，避免被主机关联程序判定为瞬移 |
| 失效兜底 | 未校准时回退到键盘 `[` / `]` 方案，屏幕提示"未校准，用键盘" |
| 前置条件 | 校准后主机光标不应被其它鼠标大幅移动（B 协议固有限制） |

**验收标准**
- [ ] 校准一次后，之后 10 次"下一集"全部命中正确（路径不漂移）
- [ ] 校准数据在设备重启后仍然有效
- [ ] 未校准时按"下一集"，设备回退到键盘方案并有屏上提示
- [ ] 相对移动分步执行，单次指令不产生瞬移
- [ ] 校准过程全程无需看 README，每步都有屏幕文字引导

### 2.4 F4 — 屏幕状态反馈（P1）

2.0 寸 IPS 屏（320×240）是**用户唯一的状态信息来源**（用户躺着，屏幕朝上）。

#### 2.4.1 屏幕内容

| 区域 | 内容 |
|---|---|
| 顶栏 | BLE 连接状态点（绿=已连接/黄=配对中/红=断开）、当前模式（遥控/鼠标/红外/校准） |
| 主区 | 大号动作反馈（最近一次触发的动作名，如"下一集""已暂停"） |
| 副区 | 提示信息（"长按校准""未连接，请先配对"） |
| 底栏 | 快捷键速查（当前模式下按键的作用） |

#### 2.4.2 模式与按钮布局（v2.0）

| 模式 | 布局 |
|---|---|
| **遥控模式** | 主行 3 个大按钮（上一集/下一集/播放暂停）+ 次行 6 个按钮（音量-/音量+/全屏/鼠标/红外/校准） |
| **鼠标模式** | 左右两侧各一个 58×200 竖长**按住型按键**（左键/右键），中间为触控板，底部中央「遥控」出口 |
| **红外模式** | 学习/发射/换下一个槽/返回 四个按钮，卡片显示槽位与已学数量 |
| **校准模式** | 校准下一集/校准上一集/完成 |

**鼠标模式左右键（v2.0 新增）**

- 按下立即发送 `mouse button down`，抬起才发送 `up`（按住型，非点击型）；
- 按住后手指拖到中间触控板区域 = **按住拖拽**（框选、拖窗口），与真实鼠标一致；
- 解决的问题：触摸屏只能发"轻点"，此前没有任何方式发出"按住不放"的鼠标键；
- 右键按钮同时是 macOS 上可靠的右键来源（不依赖系统识别鼠标按钮 2）。

#### 2.4.3 反馈原则

- **动作发生后立即反馈**（<100ms），不等到下一次操作
- **区分主动作与次动作**：主区大字显示，次区小字补充
- **断线时屏幕必须亮起提示**——不能让人以为设备坏了
- 息屏状态下的第一下触摸**只用于唤醒屏幕**，不执行任何动作（防止摸黑找按钮时误暂停视频）

**验收标准**
- [ ] 每次按键触发后屏幕立即显示对应动作名
- [ ] 断线时屏幕顶栏变红并显示"未连接"
- [ ] 屏幕内容在 320×240 内不溢出、不重叠（`tools/preview_ui.py` 离线校验四屏全部通过）
- [ ] 鼠标模式按住左键拖动，主机出现连续选区/拖拽
- [ ] 息屏后轻点屏幕只亮屏不点击

### 2.5 F5 — IMU 体感手势（P1）

利用板载 QMI8658 六轴传感器：

| 手势 | 检测方式 | 动作 |
|---|---|---|
| 甩腕 | 陀螺仪 Y 轴角速度峰值 > 200°/s | 快进 10 秒 |
| 翻转 | 加速度计 Z 轴符号翻转 | 播放 / 暂停 |
| 倾斜保持 | 姿态角偏离水平 > 45° 持续 2s | 音量增减（倾左减/倾右增） |

**验收标准**
- [ ] 甩腕误触发率 < 5%（静止持握 60 秒内不误触发）
- [ ] 体感灵敏度可通过 NVS 调节（3 档）

### 2.6 F6 — 配置持久化（P1）

### 2.7 F7 — 红外遥控学习与发射（P1，v2.0 新增）

同一块设备兼任**万能遥控器**：把任意红外遥控器（电视/机顶盒/空调/风扇）的按键
学习下来，之后在屏幕上一键回放。躺在床上看剧时顺手关电视、调音量。

#### 2.7.1 工作原理

| 环节 | 实现 |
|---|---|
| 发射 | RMT TX 通道 + 38kHz 载波（占空比 33%），包络由 RMT 硬件产生（1 tick = 1us） |
| 学习 | RMT RX 捕获原始波形（电平+时长对），**不解析协议**，原样存储 |
| 回放 | 学习到的 symbol 数组用 copy encoder 原样重放（同一份数据） |
| 存储 | 4 个槽位，每槽最多 96 个 symbol；**NVS + 独立 `irbank` 分区双副本**（见 2.7.4） |

#### 2.7.4 数据持久化（双副本，抗擦写）

学一次码要按着遥控器等好几秒，丢了最恼人，所以不把鸡蛋放一个篮子：

| 副本 | 位置 | 作用 |
|---|---|---|
| 主 | NVS（namespace `bilimouse`，key `irbank`） | 常规读写路径 |
| 镜像 | 独立 flash 分区 `irbank`（0x200000，64KB） | NVS 被整体擦除时的兜底 |

- **写入**：两条路径都写；镜像区用 4KB 扇区 A/B 轮换，「擦旧页 → 写 → 回读校验」，
  写一半掉电也不会同时毁掉两份。每条记录带 `magic + version + seq + CRC32`。
- **加载**：两份都读，取「序号更大且 CRC 通过」的那份；另一份缺失或过期就自动补齐。
- **当前槽位**单独存 `ir_act`，重启后回到上次用的槽，不会跳回槽 1。
- **老固件升级**：v1 格式（`IRB1`）自动迁移到 v2，已学的码不丢。

| 场景 | 结果 |
|---|---|
| 重启 / 断电 / 拔电池 | ✅ 不丢 |
| `idf.py flash` 重新烧录固件 | ✅ 不丢（烧写只覆盖 bootloader / 分区表 / app） |
| NVS 因 `NO_FREE_PAGES`/版本不符被整体擦除 | ✅ 不丢（从 `irbank` 镜像自愈） |
| 分区表里 `irbank` 被移除或偏移被改 | ✅ 不丢（从 NVS 重建镜像） |
| `idf.py erase-flash`（整片擦除） | ❌ 会丢（这是物理清空） |
| `partitions.csv` 里 `nvs` 的 offset 被改 | ❌ 会丢（**不要动 0x9000**） |

**为什么不用文件系统 / SD 卡**：单一分区即可，无挂载开销、无掉电丢 FAT 表风险；
红外码体积只有 ~1.5KB，NVS 与裸分区都绰绰有余。

**为什么"原样录制"而不是"解析 NEC 再编码"**：空调等设备普遍使用非标准协议
（ NEC 变体、 位宽不同、带校验和的私有格式），解析器只对标准 NEC 有效；
原始波形录制对**任何**能被接收头收到的信号都有效，鲁棒性最高。
另提供 `bsp_ir_send_nec(addr, cmd)` 标准 NEC 发射接口，供程序化控制使用。

#### 2.7.5 交互流程

```
遥控模式 → 点「红外」→ 红外页面（显示当前槽/已学数量）
  ├─ 点「学习」→ 独立任务阻塞等待 8 秒，屏幕提示"对准设备按一下遥控器"
  ├─ 点「发射」→ 回放当前槽
  ├─ 点「换下一个槽」→ 循环切换 4 个槽
  └─ 点「返回」→ 回遥控模式
```

#### 2.7.6 硬件接线（外接，板载无红外器件）

| 器件 | 引脚 | 说明 |
|---|---|---|
| 红外发射 LED（或发射模块） | **GPIO10** | 板载 GH1.25 扩展口；建议串 100Ω 限流电阻，long 距离发射加 NPN 三极管驱动 |

**验收标准**
- [ ] 学习一次 NEC 遥控器按键后，发射能让电视/机顶盒正确响应
- [ ] 学习数据重启后仍在（NVS 与 `irbank` 两份副本都可单独恢复）
- [ ] 手动擦除 NVS 后重启，码仍在且 NVS 被自动补回
- [ ] 4 个槽位可独立学习/发射/切换，当前槽号重启后保持
- [ ] 学习等待期间屏幕可正常操作（「返回」可用，不卡 UI）
- [ ] 未接红外硬件时其余功能不受影响，红外按钮提示"不可用"

### 2.8 F8 — 省电模式（P1，v2.0 新增）

USB 供电场景下功耗不是硬约束，但床头设备 7×24 常亮刺眼且发热。v2.0 增加
**三档空闲省电**：

| 状态 | 触发 | 行为 |
|---|---|---|
| ACTIVE | 默认 / 任意操作后 | 正常亮度（默认 80%），触摸 20ms 轮询，界面 20fps 刷新 |
| DIM | 空闲 30s | 背光降到 25%（保底 5%），交互照常 |
| SLEEP | 空闲 90s | 背光 0（息屏），界面停止刷新，触摸轮询降到 150ms |

- **唤醒即响应**：任何触摸/实体键立刻恢复 ACTIVE，且息屏后的第一次触摸
  只亮屏不触发动作（见 §2.4.3）；
- **BLE 保持连接**：不做 light sleep——BLE HID 在 light sleep 下会断链、
  唤醒后要重新加密，对"躺下按一下"的体验伤害大于收益；背光与轮询频率
  才是这块板子的耗电大头；
- 亮度写入 NVS（`backlight`），重启后保持。

**验收标准**
- [ ] 空闲 30s 背光自动变暗、90s 息屏
- [ ] 息屏后轻点屏幕立即点亮，且这次触摸不产生点击/移动
- [ ] 息屏期间 BLE 连接保持，实体键空格仍生效
- [ ] 调整亮度后重启，亮度保持

## 3. 非功能需求

| 类别 | 指标 |
|---|---|
| **连接稳定性** | 断线自动重连；配对信息持久化，重启后自动回连 |
| **响应延迟** | 按键到 HID 报告发出 < 30ms；动作到屏幕反馈 < 100ms |
| **功耗** | USB 供电；空闲 30s 变暗 / 90s 息屏（F8）；息屏时触摸轮询 150ms；蓝牙连接间隔 30~50ms（平衡延迟与功耗） |
| **资源占用** | Flash ≤ 2MB，RAM 峰值 ≤ 200KB（不含 PSRAM） |
| **可靠性** | 连续运行 72 小时不崩溃、不丢配对 |
| **可维护性** | 模块化 BSP / HID / 交互 / UI 分层；引脚集中可配；核心逻辑有单元测试 |
| **可移植性** | BSP 层与业务层解耦，换板子只改 BSP |

## 4. 技术架构

```
┌─────────────────────────────────────────────────────────┐
│                        应用层                            │
│  交互状态机(button_fsm) → 动作映射(action_map) → HID 报告 │
│         ↑                    ↑                            │
│    IMU 手势(imu)        坐标记忆(NVS)                     │
└─────────┼────────────────────┼───────────────────────────┘
          │                    │
┌─────────▼──────────┐  ┌──────▼───────────────────────────┐
│   BLE HID 层        │  │   UI 层 (LVGL → ST7789 → 触摸)   │
│  鼠标/键盘/消费类    │  │   状态反馈 + 校准界面             │
└─────────┬──────────┘  └──────┬───────────────────────────┘
          │                    │
┌─────────▼────────────────────▼───────────────────────────┐
│                    BSP 板级驱动层                        │
│  PCA9557(IO扩展) · ST7789 · FT6336触摸 · QMI8658 · GPIO0 │
└──────────────────────────────────────────────────────────┘
```

### 4.1 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | ESP-IDF **v6.0.2** | 本机已有；蓝牙栈成熟；与同板既有项目一致 |
| 蓝牙栈 | **Bluedroid**（非 NimBLE） | BLE HID over GATT profile 官方支持最完整 |
| HID 实现 | 基于官方 `ble_hid_device_demo` 改造 | 复用官方报告表与 GATT 服务，避免自研踩坑 |
| 屏幕 | 自写 ST7789 驱动（esp_lcd + SPI） | 避免依赖外部组件仓库，保证离线可编译 |
| 触摸 | FT6336 I2C 驱动 | 校准/设置界面需要触摸交互 |
| IMU | QMI8658 I2C 驱动 | 体感手势 |
| UI | LVGL 8.x | 320×240 图形界面开发效率高 |

### 4.2 Flash 分区表（v2.1 起启用自定义表）

之前很长一段时间 `partitions.csv` 是**死文件**——sdkconfig 停留在默认的
`partitions_singleapp.csv`，改它没有任何效果。v2.1 起真正启用自定义表：

| Name | Type | Offset | Size | 说明 |
|---|---|---|---|---|
| `nvs` | data/nvs | **0x9000** | 24KB | 键值区：设置、校准、红外码主副本 |
| `phy_init` | data/phy | 0xf000 | 4KB | RF 校准数据 |
| `factory` | app | 0x10000 | 1984KB | 应用（当前占用 ~830KB，余 58%） |
| `irbank` | data/0x40 | **0x200000** | 64KB | 红外码镜像区（A/B 双扇区） |

**约束**：`nvs` 与 `irbank` 的 offset 是写死的，不能改成自动排布也不能移动——
一旦偏移变化，用户已经存在那里的数据就永远读不回来了。新增分区一律往后追加。

### 4.3 硬件引脚表（已对真机验证）

| 功能 | 引脚 | 说明 |
|---|---|---|
| I2C SDA | GPIO1 | PCA9557 / FT6336 / QMI8658 / 音频芯片共用 |
| I2C SCL | GPIO2 | 同上 |
| LCD SCK | GPIO41 | SPI3 |
| LCD MOSI | GPIO40 | SPI3 |
| LCD DC | GPIO39 | |
| LCD RST | GPIO38 | |
| LCD BL | GPIO42 | 低电平点亮，PWM 调光 |
| LCD CS | PCA9557 IO0 | **必须先经 IO 扩展拉低才可显示** |
| 用户按键 | GPIO0 | 低电平按下（BOOT 键复用） |
| 红外发射 | GPIO10 | v2.0 新增，板载 GH1.25 扩展口，外接发射 LED |
| 红外接收 | GPIO11 | v2.0 新增，外接 38kHz 一体化接收头（输入反相已开） |
| 板载 LED | GPIO48 | |
| PA_EN | PCA9557 IO1 | 音频功放（本产品不用） |
| DVP_PWDN | PCA9557 IO2 | 摄像头（本产品不用） |

> **关键坑位**：PCA9557 上电默认 IO 为输入状态，LCD_CS 悬空导致屏无响应。初始化必须先写 `OUTPUT=0x03`、`CONFIG=0xF8`，再拉低 IO0。

## 5. 用户体验设计

### 5.1 首次使用流程（目标：3 分钟内可用）

```
上电 → 屏幕亮起，显示"BiliMouse 待配对"
     → 用户在 PC 蓝牙设置搜索并配对
     → 屏幕顶栏变绿，显示"已连接"
     → 屏幕提示"长按进入校准"
     → 用户长按校准，鼠标移到 B 站"下一集"按钮，短按确认
     → 屏幕显示"校准完成"
     → 单击设备 → 视频切换成功 → 屏幕显示"下一集" ✅
```

**设计要点**：全程无需看 README，无隐藏手势。每个步骤都有屏幕文字引导。

### 5.2 日常使用（躺着）

```
手握设备举在眼前（屏幕朝上）→ 看一眼屏幕确认状态 → 单击 → 下一集
```

- 屏幕亮度默认 80%，可调至 20% 夜间模式
- 反馈动画简短（150ms），不打断观看节奏
- 双击回上一集，长按暂停——都是肌肉记忆-able 的标准手势

### 5.3 边界情况处理

| 情况 | 处理 |
|---|---|
| 未连接时按键 | 屏幕提示"未连接"，不发送任何 HID 报告 |
| 未校准就按"下一集" | 回退键盘方案 + 屏幕提示"建议先校准" |
| 校准坐标失效（页面改版） | 屏幕提示"点击未命中，请重新校准" |
| IMU 误触发 | 静止检测窗口内抑制；灵敏度可调 |
| 主机休眠后 | BLE 自动重连，屏幕状态同步刷新 |

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| Windows 对 BLE HID 的兼容性/配对流程 | 高 | 使用官方 ble_hid_device_demo 同款实现，报告表对齐官方定义 |
| B 站页面改版导致坐标失效 | 中 | 键盘兜底路径 + 屏幕提示重新校准 |
| "下一集"按钮位置因浏览器/窗口尺寸不同而异 | 中 | 校准以用户实际屏幕为准，天然自适应窗口大小 |
| 单键多义的时序误判 | 中 | 严格状态机 + 单元测试 + 300ms 判定窗口 |
| IMU 体感误触发 | 低 | 静止抑制 + 三档灵敏度 |
| 屏幕显示吃掉过多 RAM | 低 | 320×240×16bit 单缓冲仅 150KB，放 PSRAM |
| 长按与双击判定冲突 | 低 | 长按触发后立即锁定当前手势，不再响应后续判定 |
